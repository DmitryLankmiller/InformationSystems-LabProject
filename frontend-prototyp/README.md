# Cityspace — прототип интерфейса

Отдельная копия `frontend` на React и TypeScript. Исходный фронтенд не изменяется.

Визуальный образец — [Twenty CRM](https://docs.twenty.com/getting-started/core-concepts/layout): таблица записей, панель инструментов и просмотр сущности справа. Основной текст — 16 px, заголовки страниц на десктопе — 40 px. Используется собственная реализация интерфейса.

## Запуск

Из корня проекта:

```sh
cd frontend-prototyp
npm ci
npm run dev
```

Откройте http://localhost:5174. Бэкенд должен работать на http://localhost:8080: Vite перенаправляет `/api` на этот адрес.

```sh
npm run build
npm run lint
```

Для другого API задайте `VITE_API_URL` в локальном `.env.local`, например:

```dotenv
VITE_API_URL=http://localhost:8080/api
```

При прямом запросе с другого origin серверу нужен CORS. Для размещения сборки `dist` настройте проксирование `/api` к бэкенду либо задайте адрес API перед сборкой. Прокси Vite работает только в режиме разработки.

## Возможности

- Таблица всех атрибутов города, пагинация, фильтры названия и имени губернатора.
- Несколько правил сортировки с изменением приоритета.
- Поиск по ID, карточка с координатами и губернатором.
- Создание, частичное обновление и подтверждение удаления.
- Новый губернатор или выбор существующего из списка / по ID.
- Все пять специальных операций и проверки приложения и БД.
- Проверка полей, сообщения об ошибках, адаптивная вёрстка и управление диалогами с клавиатуры.

Поля проверяются при потере фокуса; после первого выхода из поля ошибки обновляются при вводе. При отправке форма повторно проверяет все поля. Поддерживаются дробные числа с запятой или точкой, календарная проверка дат и сообщения на русском для серверных ошибок, отсутствующих объектов, проблем связи и некорректного ответа API. Неизвестные технические подробности пользователю не показываются.

Таблица и открытая карточка обновляются каждые 5 секунд, проверки состояния — каждые 10 секунд. Форма редактирования при этом не перезаписывается.

API описан в `../docs/openapi.yml`. Типизированные запросы находятся в `src/api.ts`. Список губернаторов собирается из городов: отдельного HTTP-ресурса для них пока нет; для губернаторов без городов можно указать ID вручную. API пока не поддерживает смену губернатора при редактировании города. Сортировка по имени губернатора зависит от исправления соответствующей ошибки бэкенда.
